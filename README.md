# Yugsight（御视）· 网络扫描探测工具

**简体中文** | [English](README.en.md)

基于 Go 单文件 exe 的网络扫描探测工具，内置 Web UI（启动后浏览器自动打开），开箱即用、离线可跑：除 YAML 解析（`gopkg.in/yaml.v3`，用于 Nuclei 模板）外全部标准库实现，不依赖任何外部服务与前端资源。

- **中心端**：单文件 exe，内含 Web UI 与全部扫描能力；不装任何外部引擎也能完整工作。
- **探针端**：独立小程序（`yugsight-agent.exe`），装在被扫描机器上，只向中心端发起一条出站连接，零入站端口。

## 功能模块

| 模块 | 说明 |
|---|---|
| IP 存活扫描 | CIDR / IP 范围 / 单 IP，ICMP + TCP 双探测，strict/loose/不判存活三模式 |
| 端口扫描 | 自定义端口，支持 `80,443,500-600` 列表+范围混合，服务名/横幅/延迟 |
| Web 漏洞扫描 | 安全响应头、TLS 证书、35+ 敏感路径、SQLi/XSS/路径穿越探测 + 漏洞库规则（可按规则勾选、降噪：缺失响应头合并为单条加固建议） |
| Web 深度扫描（可选） | 同源爬取 → 表单/参数注入点 → SQLi 三类 + XSS 三位置（默认关闭） |
| 主机扫描 | 系统指纹（TTL/端口组合推断 OS）、TLS 证书、服务横幅版本、按服务常见风险检测（Redis 未授权等）、CPE 字典匹配具体 CVE+CVSS，只列开放端口 |
| 外部引擎（可选） | nmap / trivy / ZAP / nuclei 一键下载安装到 `bin/`，扫描编排优先外部引擎、失败自动降级内置引擎 |
| 弱口令 / 空口令（可选） | 10 种协议（redis/mysql/postgresql/ftp/telnet/ssh/smb/vnc/rdp/oracle）真实试探，top100 内置字典 + 自定义字典，CIDR 白名单 + 限速 + 审计，默认关闭 |
| 实时抓包 | Npcap（UI 内一键安装）、全量采集 + 页面过滤、报文列表/详情/十六进制、环路检测（默认关） |
| Nuclei 模板扫描 | 内置 5 个模板（打包进 exe）+ 外部模板，tag 黑白名单过滤，热更新，官方仓库在线更新 |
| 漏扫管控 | 白名单（ip/cidr/port/cve/tag）+ 人工误报标记（后续扫描自动标记）+ 置信度打分 |
| 分布式扫描 | 中心端 + 独立探针 agent：节点信息上报、任务下发、探针本地扫描/抓包/枚举/SYN、探针包下载与自动更新 |
| 节点监控 | 阶段 1 采集底座：主机侧（agent 探针 + 无代理 WinRM/SSH/主机 SNMP）+ 网络侧（SNMP + ICMP/NetFlow/NETCONF/RESTCONF），任务调度/限速/白名单/时序/异常事件（默认关闭） |
| 任务调度 | 排队执行、优先级/并发/网段限速、策略模板、探针路由（默认启用；普通即时扫描不受影响） |
| 漏扫报告 | 一键导出 HTML 报告、自定义模板；报告引擎（可选）：风险评分/修复建议/资产拓扑/历史两扫对比、扫描结束自动触发 |
| 报告中心（原始报告） | 抓包 / 扫描 / 弱口令 / 节点监控执行完成后，原始结构化结果自动存档；单份查看、多选合并为汇总报告、标签 / 来源 / 时间 / 资产筛选；业务页 AI 分析的研判结果挂载在对应报告下，原始数据 + AI 研判可同时查看，合并时 AI 内容随源报告保留 |
| 首页仪表盘 | 双 Tab 页面：概览仪表盘（资产/风险/任务/引擎 + **中心端运行状态**：中心主机 CPU/内存/磁盘、服务运行时长、任务队列实时进度、探针连接/数据库/消息队列链路状态，5 秒轮询）+ 安全大屏（原独立大屏页全量迁入） |
| 安全运维大屏 | 大屏：资产/风险/趋势/探针负载/高危 TOP/3D 地球流向/SNMP 监控/热力图，可选 Prometheus 指标端点（阶段 4 起为首页仪表盘内置 Tab2，旧 `/bigscreen` 地址自动重定向） |
| AI 全链路分析（可选） | AI 配置页统一管理：接口参数 / 三套 Prompt 模板 / RAG 文档库（上传分片向量化）/ 结构化记忆库（平台历史数据检索）；分析触发按钮在各业务页面，结果存报告中心；Ollama/OpenAI 兼容，强制脱敏，默认关闭 |
| 渗透工作台（仅管理员） | 阶段 5：只对漏扫管控已登记的**已知漏洞**做验证渗透（扫描只发现、渗透只验证）。内置 EXP 模板库（可导入自定义）+ 弱口令凭据验证，SSE 实时回显，输出 可利用 / 部分利用 / 不可利用 三态结论；可修正风险定级并**一键回传**漏洞管理，报告中心自动产出「扫描 + 渗透验证」整合报告。默认启用，每次执行需逐次授权确认，`penta.*` 渗透审计独立留痕（仅管理员可清空，清空动作本身留痕） |

UI 为 Vue3 前端（默认主页，`/app/`），经典单文件页在 `/classic/` 子路径仍可访问。

## 快速开始

1. 双击 `yugsight_windows_amd64.exe`（首次会弹 UAC 提权，提权后 PID 会变一次，属正常）
2. 浏览器自动打开 `http://<本机IP>:8420`（默认主页为 Vue3 前端，经典页在 `/classic/`）
3. 用初始账号 `admin / admin123` 登录（全新安装自动创建，可在 `settings.json` 的 `auth` 节修改）
4. 选择模块、填参数、点"开始扫描"，结果实时流式显示
5. 扫描完成后点"生成报告"导出 HTML 报告

- 程序以**控制台窗口**形式常驻（显示实时日志，已自动最小化）：关窗不停服务。**停止服务**只有两个入口 —— 登录页底部的"停止服务"链接、授权管理页的"服务管理 → 停止服务"按钮（`/api/quit`，免登录），或恢复控制台窗口后 Ctrl+C。
- 服务默认绑定 `0.0.0.0`（全部网卡，含回环），因此 `http://127.0.0.1:8420`、`http://<本机IP>:8420` 都能访问；机器 IP 变化（DHCP 换租 / 插拔 VPN）也不会失联。只想绑本机局域网 IP 时用 `-bind-local` 启动。
- 实时抓包模块需要 Npcap：UI 内点"一键安装"即可（使用 exe 同目录的 `npcap-1.86.exe` 官方安装器）。
- 外部引擎（nmap/trivy/ZAP 等）缺省时内置引擎照常工作；需要时在「引擎与规则」页的**引擎**页签一键下载安装。

## 角色与权限

登录用户分三种角色（在授权管理页分配）。权限边界由后端中间件兜底，前端只是隐藏入口：

| 能力 | admin 管理员 | operator 操作员 | auditor 只读 |
|---|---|---|---|
| 浏览全部页面（仪表盘 / 大屏 / 资产 / 漏洞 / 报告 / 监控） | ✓ | ✓ | ✓ |
| 发起扫描、抓包、SNMP 监控、弱口令检测 | ✓ | ✓ | ✗ 403 |
| 资产 / 漏洞 / 白名单 / 误报 / 任务 / 探针 / 引擎 / 报告 的写操作 | ✓ | ✓ | ✗ 403 |
| 渗透工作台（已知漏洞的验证渗透 / EXP 模板 / 结果回传） | ✓ | ✗ 菜单隐藏，接口 403 | ✗ 菜单隐藏，接口 403 |
| 授权管理页（用户账号、会话吊销、审计配置与清理） | ✓ | ✗ 菜单隐藏，手输地址回落首页 | ✗ |

- 只读角色看得见所有数据，但任何写接口都返回 403 —— 界面上也不会显示必然失败的按钮。
- 操作员能干活但碰不到账号体系：否则可自建 admin 账号自我提权，这是刻意的红线。

## 功能使用

左侧菜单分六组：运维总览 / 扫描作业 / **渗透测试** / 资产与风险 / 诊断与观测 / 系统配置。下面按菜单顺序讲**怎么用**（括号内是路由）。

### 典型流程

1. **扫描作业**在"立即扫描"页签选"快速发现"，填网段，先摸清存活主机与开放端口；
2. 对关注的主机跑**深度主机**（系统指纹 + 服务版本 + CVE 匹配），需要时再跑 **Web 漏洞**；
3. 结果自动落库 → 到**资产管理 / 漏洞管理**复核、改状态、标误报；
4. 需要确认"漏洞是否真能利用"时，从漏洞管理**发送到渗透工作台**做验证渗透，结论回写漏洞条目；
5. **报告中心**导出报告交付（含渗透验证章节）；日常值守看**首页仪表盘 → 安全大屏** Tab。

### 运维总览

**首页仪表盘（/）**：页面内置两个 Tab —— **概览仪表盘**（默认）与 **安全大屏**（原独立大屏页全量迁入，数据来源与刷新策略不变）。

- **Tab1 概览仪表盘**：资产总数 / 漏洞总数 / 扫描任务 / 扫描引擎 / Npcap 驱动五张卡，外加**中心端运行状态**、漏洞等级分布、引擎状态、系统信息、快捷入口与功能开关（geoip、3D 大屏、报告引擎、模板管理、PDF 外部转换、扫描后自动生成报告）。概览数据不自动刷新（点右上"刷新"取最新值）；**中心端运行状态面板独立 5 秒轮询**（`GET /api/v2/center/status`，只读聚合、逐项降级）：
  - **中心主机负载**：CPU 使用率（两次采样差分，首屏无基线显示"-"）、内存占用（已用/总量）、磁盘剩余（exe 所在盘）、服务启动时间与运行时长；
  - **任务队列状态**：等待任务数、执行中任务数（含并发槽位）、暂停数、节点采集是否在跑 + 运行中扫描/采集任务的实时进度列表；
  - **数据链路状态**：在线探针连接总数、数据库读写状态（类型/目录/各表记录数）、SSE 消息队列健康（订阅者数 + 重连补发窗口占用 + 最新事件序号）。
- **Tab2 安全大屏**：15 秒自动刷新。资产总量 / 存活资产 / 严重漏洞 / 高危漏洞 / 在线探针 / 运行中任务六张数字卡，下面是近 7 天漏洞趋势、漏洞风险占比、高危漏洞 TOP、IP 流向 3D 地球、SNMP 网络监控、漏洞热力图、探针在线状态、风险资产 TOP、最近扫描任务。可全屏 / 立即刷新 / 返回概览。

> 阶段 4 职责拆分：顶栏右上角只保留**静态版本号**（只读、随页面加载，用于快速确认程序版本），动态负载数据统一归口"中心端运行状态"面板，不再两处重复展示；独立 `/bigscreen` 菜单项移除，旧地址自动重定向到 `/?tab=screen`（书签不失效）。

**报告中心（/reports）**：两类产出 —— 原始报告（各业务模块执行后的原始结构化结果，自动存档）与渲染报告（普通报告（导出 HTML / PDF / Word）/ 对比报告 / 模板包，按钮 **预览报告 / 生成并下载 / 生成并存档**）。页签：

- **原始报告**：四大业务模块（实时抓包 / 扫描作业 / 弱口令检测 / 节点监控）执行完成后自动存入的原始结构化报告。支持按 **来源模块 / 标签 / 资产 IP / 时间范围 / 关键字** 筛选；勾选多份可**合并为一份汇总报告**（按来源模块分组、资产标签取并集、来源可下钻）；详情弹窗按模块渲染摘要表 + 原始 JSON（可复制）+ **AI 分析**区块（业务页触发的研判全文、模型/模板/RAG/记忆元数据；未分析的报告会提示去业务页触发）。已 AI 分析的报告带 **AI** 徽标，合并时 AI 内容随源报告保留（来源表可见、可逐源展开）。存满自动淘汰最旧（`report.maxRaw`，默认 500 份）；自动存档开关 `report.autoSave`（默认开）。
- **存档**：历史渲染报告 下载 / 删除；
- **历史对比**：做两轮扫描对比（基线自动取前等长区间），得到 新增 / 修复 / 持续存在 三分桶，可把对比报告存档；
- **模板管理**：默认隐藏，右上「高级」开关才显示（选择记在浏览器本地），可编辑 / 保存 / 删除模板与模板包。

PDF 走浏览器打印通道（用浏览器另存为 PDF），Word 由服务端直接产出。

### 扫描作业

**扫描作业（/console）**：两个页签（原"实时扫描控制台"与"扫描任务管理"合并为一页，旧 /scans 地址重定向到"任务队列"页签）。

- **立即扫描**（默认）：提交区是共用表单 —— 扫描类型三种（见下表），"提交方式"可选 **立即执行**（默认，SSE 实时出结果）或 **排队执行**（调度器派发；选中后出现调度参数：策略模板（服务端下发或 custom 不套模板）/ 执行节点：中心本地或指定探针或 auto / 优先级：数字小者先跑 / 失败自动重分配）。立即执行开始后结果按事件流实时刷出（状态 / 存活 IP / 端口 / 漏洞 / 完成），下方分"漏洞结果"与"开放端口"两栏，点条目看详情。
- **任务队列**：调度任务表（状态筛选 + 4 秒自动刷新，行内可 暂停 / 恢复 / 取消 / 重试 / 删除）+ 策略模板列表 + 限速统计（默认 pps、按网段令牌桶）。

| 类型 | 目标填法 | 专属参数 |
|---|---|---|
| 快速发现 | 网段 CIDR（如 `192.168.1.0/24`） | 端口集（`80,443,500-600`）、存活判定（loose 宽松 / strict 严格 / none 不判，仅立即执行）、仅存活检查 |
| 深度主机 | 单个目标 IP | 启用 Nuclei、tag 白名单 / 黑名单 |
| Web 漏洞 | 目标 URL（`http://…`） | 深度爬取（表单 / 参数注入点）、漏洞库规则勾选（默认全选，只勾部分即只跑这些规则，仅立即执行） |

通用参数是超时（毫秒）与并发（排队执行时用户填的值覆盖策略模板默认值）。

**弱口令检测（/weakpass）**：**默认关闭**，需在 `settings.json` 的 `authcheck` 节启用（目标 CIDR 白名单 + 限速），改完重启生效；页面顶部会提示当前是否启用。目标一行一个：`host:port[:service[:user]]`，单次最多 200 行。协议清单来自服务端配置（页面只读展示，未实现可靠判定的协议如 MSSQL 不展示）。"结论"列分四种：弱口令 / 空口令免认证 / 协议不支持 / 未命中；另有"审计明细"页签（每次尝试都落审计，口令只在命中时出现）。

### 渗透测试

> 阶段 5 的**职责隔离**：扫描模块只做广谱探测发现漏洞、不执行漏洞利用；渗透工作台只对漏扫管控里已登记的**已知漏洞**做验证渗透、不做广谱扫描。两端的菜单、接口与权限都物理隔离。

**渗透工作台（/penta）**：三个页签，仅 **admin 管理员**可见可用（operator / auditor 菜单无入口，手输地址回落首页，接口 403）。

- **渗透任务管理**（默认）：按 状态（待执行 / 执行中 / 完成 / 失败）/ 风险等级 / 目标 筛选；可**新建任务**（目标 + 端口 + 协议 + CVE + 标题 + EXP 模板 + 初始定级），或用**从漏扫管控导入**弹窗勾选漏洞批量导入（已导入过的漏洞自动跳过，重复点击不会产生重复任务）。多选后可**批量删除 / 批量导出**（导出是含证据的 JSON 附件）。行内 执行 / 结果 / 删除。
- **渗透执行控制台**：左栏 选任务 + **EXP 模板库**（内置模板 + 自定义导入，按 tag / 名称 / CVE / ID 筛选，选中后展开"每一步将做什么"）；右栏 执行参数（弱口令类模板可填账号与候选口令，上限 10 个 —— 这是凭据验证场景，不是爆破）、**授权确认勾选**与执行按钮、实时回显控制台。执行走 SSE 流式输出（逐步线、每步命中与否、耗时、结论），执行中任务不允许重复执行或删除。
- **渗透结果管理**：逐条修正**可利用性结论**（可利用 / 部分利用 / 不可利用）与**风险定级**（保持扫描定级或改为严重/高危/中危/低危/信息）、填写摘要；展开**证据**（每个步骤的命令与响应留存、执行日志）；点**回传**把结论同步回漏洞管理对应条目。目标不可达时不会给出"不可利用"结论，而是标记失败并保持无结论 —— 避免把"连不上"误报成"打不动"。

**EXP 模板库**：内置常见 CVE / 服务的验证脚本（Redis 未授权、HTTP 目录列举、TLS 信息、TCP Banner、弱口令验证等），支持粘贴 YAML / JSON **导入自定义模板**。安全边界在服务端：步骤类型只允许 `http / tcp / weakpass / external`（不接受任意命令执行），模板 ID 走白名单（即文件名，杜绝路径穿越），单模板口令数上限 10，与内置同 ID 拒绝覆盖。可选对接外部渗透引擎（`external` 步骤，`bin/` 下有二进制才启用）。

**联动流程**（扫描发现 → 渗透验证 → 闭环管理）：

1. 扫描作业 / 弱口令检测产出漏洞，汇入**漏洞管理**；
2. 漏洞管理勾选漏洞点**发送到渗透工作台**（详情页也可单条发送；弱口令结果行的「验证」会把目标/端口/服务带过去预填），自动填充目标与漏洞信息并按协议/端口/标题推荐 EXP 模板；
3. 渗透工作台执行验证，生成三态结论与证据；
4. 点**回传**把结论写回漏洞条目（验证结论 + 验证后定级 + 渗透任务 ID + 回传时间），漏洞管理与详情页的「渗透验证」列/字段随之更新；
5. **报告中心**生成的报告自动带上「渗透验证结果」章节（目标 / 对象 / CVE / 结论 / 定级 / 摘要 / 时间 / 操作者），漏洞明细表新增「渗透验证」列 —— 形成「扫描 + 渗透验证」整合报告。

**合规与审计**：

- 页面顶部常驻**安全声明**：仅可用于自己拥有或已获书面授权的目标，未经授权对他人系统实施渗透可能违反《中华人民共和国网络安全法》及相关法律法规。
- **权限**：全部渗透接口 `requireAuth + adminOnly`，比扫描模块的 admin/operator 更严（攻击性能力不给操作员）。
- **逐次授权**：每次执行都必须勾选"我确认已获得该目标的书面授权"，授权态不落地、刷新即失效；未勾选服务端直接 400。
- **全程留痕**：任务创建 / 导入 / 执行 / 每一步探测 / 结果保存 / 回传 都写 `penta.*` 渗透审计（含目标、模板、步骤、命中与否）。渗透审计**独立成表**（`data/penta_audit.jsonl`，与授权管理里的通用审计分离，在渗透工作台「渗透审计」页签查看）。记录**仅管理员可清空**（`DELETE /api/v2/penta/audit`，分发/数据交接场景需要干净状态；页面需输入"清空"二次确认），且清空后必写一条 `penta.audit.clear` 痕迹（谁、何时、清了几条）—— 记录可以清，但"被清过"永远可审计，与通用审计"清空日志留痕"同口径。表不提供单条删除/裁剪方法，删除路径收敛在 DAO 的 `Clear()` 一处。
- 模块总开关在 `settings.json` 的 `penta` 节（`{"enabled": false}` 停用执行能力，默认启用）；默认启用是因为本模块无任何自主行为，逐次授权 + 全程留痕已是比配置开关更强的控制。

### 资产与风险

**资产管理（/assets）**：扫描结果自动落库的资产台账（IP / 存活 / 主机名 / 操作系统 / 主服务 / 开放端口 / 探针节点 / 标签 / 发现时间）。可按 IP、按标签筛选；「新增资产」或行内「编辑」手工补录（IP、MAC、主机名、OS、探针节点、主服务、服务版本、Banner、开放端口、标签），行内「加标签」管理标签。"存活"列区分是否探测到响应。

**漏洞管理（/vulns）**：五个筛选条件（等级 / 状态 = 开放或已修复 / CVE / 资产 IP / 标题关键字），按钮 **查询 / 重置筛选 / 清空全部漏洞**。清空是破坏性操作（**只清漏洞表，资产台账不动**），需在弹窗里输入"清空"二字才能提交，且会写审计。点任意一行进详情页：可标记已修复 / 恢复为开放、标记误报（带备注，之后同资产同 CVE 自动标记）/ 取消误报、删除；下面展示描述、验证证据、原始请求与响应、PCAP 证据附件。

**漏扫管控（/whitelist）**：三个页签。
- **白名单**：类型 ip / cidr / port / cve / tag + 匹配值 + 原因 + 有效期，命中即过滤不推送；
- **误报**：资产 IP + CVE（无 CVE 时用标题）+ 备注，标记后扫描结果自动带误报标记；
- **置信度评分**：四级打分模型与风险等级映射的只读说明。

### 诊断与观测

**实时抓包分析（/capture）**：Windows 需先装 Npcap（页面内有「安装 Npcap」按钮）。选网卡 → 可选 BPF 过滤器 → 开始抓包。默认**全量采集**：内核只做 `arp or ip` 粗筛，细过滤放在页面上做，换视角不必重抓；展示层过滤词支持 `ip: / port: / proto: / mac: / src: / dst:` 前缀，多个词是"与"关系。报文表列 时间 / 协议 / 源 / 目的 / 长度 / 摘要，点行看字段详情与十六进制 dump；环路检测等统计在信息卡里（开关走 `settings.json` 的 `capture` 节）。PCAP 落盘导出当前未做，仅提示用外部工具按需抓取。「抓包分析」卡有 **AI 分析** 按钮（抓包中点击 = 先停止并存档本会话，再分析；结果存报告中心，见「AI 全链路分析」节）。

**节点监控（/nodemonitor）**：主机侧与网络侧的统一监控入口，页内两个 Tab（完整能力见下文「节点监控」专节）：

- **探针节点管理**（默认）：原「探针管理」全部功能（yugsight-agent 节点表 / 任务下发 / 下载探针 / 任务明细）+ **主机侧扩展采集（无代理）**——WinRM / SSH 命令采集 / 主机 SNMP，目标机上装不了探针时走协议采集；
- **网络设备监控**：既有 SNMP 设备监控（v2c/v3 目标、轮询间隔 ≥5 秒、CPU / 内存 / 流量 / 接口 up 数、随时「立即采集一轮」，全程只读 GET/GETBULK 不改设备配置）+ **网络侧扩展采集**——ICMP 链路探测 / NetFlow·IPFIX 流量接收 / NETCONF / RESTCONF。

页面底部是两 Tab 共用的公共区：**采集配置**（总开关 / 间隔 / 并发 / 全局限速 / 保留时长 / IP 白名单 / NetFlow 接收 / 告警阈值，写入 `settings.json` 的 `collect` 节，保存即生效）+ **异常事件**（离线 / 恢复 / CPU / 内存 / 时延 / 丢包越限，边缘触发，保留 30 天）。旧 /probes、/monitor 地址保留为重定向，书签不失效。

### 系统配置

**引擎与规则（/env）**：两个页签。
- **引擎**：探测本机 `bin/` 下的 nmap / trivy / ZAP / nuclei 与 Npcap 驱动状态，按钮有「重新检测」「一键安装引擎」（支持代理 / 镜像 / 自动测速，ZAP 会连带装一个隔离的 JDK 17）「刷新可下载列表」「安装网络驱动」「重载引擎配置」。引擎缺失只降级到内置引擎，不影响扫描。
- **规则**：内置漏洞库 + 自定义规则一览，可按 scope（Web / 主机）、等级、匹配方式（body / header / path）、关键字过滤，可"标记已验证"；「导入自定义规则」粘贴 JSON 即写入 `vuln/` 并立即生效（格式见"漏洞库"节）。

> 探针管理已并入「诊断与观测 → 节点监控」的**探针节点管理** Tab（原 /probes 地址重定向过去），部署口径见「分布式扫描」节。

**AI 配置（/settings/ai）**：AI 全链路分析的统一配置页（分析**触发**入口在各业务页面，本页只管配置）。四个板块：
- **① 接口基础配置**：API 地址 / Key / 模型 / 请求超时 / 最大上下文长度 / 最大输出 token / temperature / top_p；「测试并保存」（连通通过才落盘启用，热生效免重启）；三个**模块总开关**（实时抓包 / 扫描结果 / 节点监控告警）—— 关闭后对应业务页的"AI 分析"按钮置灰。
- **② Prompt 模板**：三套预设（流量分析 / 漏洞报告 / 监控告警研判，弱口令与节点采集分别复用后两套），语法高亮编辑器，占位变量 `{{raw_data}} {{asset_info}} {{scan_result}} {{metric_data}} {{time}} {{structured_memory}}`；每套模板独立的 **RAG 绑定开关 + 检索条数**；保存 / 恢复默认。业务页点 AI 分析时自动绑定对应模板。
- **③ 文档库（RAG，非结构化）**：上传安全基线 / 漏洞手册 / 设备资料 / 运维文档（文本类，≤2MB），自动**分片 + 向量化**（内置 TF-IDF 向量引擎，纯离线、不依赖外部 embedding 服务），启用 / 禁用 / 删除 / 检索预览。
- **④ 结构化记忆库（与 RAG 严格区分）**：RAG 查"上传的文档"，记忆库查**平台数据库内的结构化历史** —— 资产历史扫描记录 / 历史告警事件 / 历史抓包分析记录 / 节点历史指标（范围可勾选），全局总开关 + 保留时长 + 每范围条数上限 + 压缩开关；AI 分析时检索结果自动注入 `{{structured_memory}}` 变量。

**授权管理（/license，仅管理员可见可进）**：四个区块。

- **账户**：当前用户 / 角色 / 注册状态（只读）；
- **用户管理**：创建账号（用户名 + 初始密码 + 角色下拉：只读 / 操作员 / 管理员）、改密、切换角色、停用 / 启用、删除（唯一启用的管理员不允许降权，避免把自己锁死）；
- **登录会话**：列出在线会话（token 脱敏），可「吊销」；
- **审计日志**：按 用户 / 动作 / 关键字 / 起止日期 筛选；「清空日志」清空全部，行内「删除」删单条 —— 均仅管理员可用，且清理动作本身会留一条 `audit.clear` / `audit.delete` 记录（保留天数由服务端审计配置决定）。这里**不含渗透审计**：`penta.*` 已分离到渗透工作台的「渗透审计」页签独立留痕（仅管理员可清空，清空动作留 `penta.audit.clear` 痕迹），合规留痕不因本表清理而消失；
- **服务管理**：停止服务（等价登录页底部的「停止服务」链接）。

**经典单文件页（/classic/）**：老的 9 页签界面（IP 存活 / 端口扫描 / Web 漏洞 / 主机扫描 / 抓包分析 / 漏洞规则库 / 白名单误报 / 实时事件 / 引擎状态）仍可直接访问，Vue 界面里没有入口；用 `-ui old` 启动可把它设为主页。

## 构建与重新编译

前置：Go 1.25+；改动前端时另需 Node 20+（开发用 Node 22 / npm 10）。

```powershell
# 推荐: 构建脚本(自动注入图标与版本号, 多平台可选, 产物名带平台后缀)
powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -OutDir dist
# 只构建 Linux 服务端: -Targets linux/amd64
# 不动版本号只重编一次: -NoBumpVersion; 试构建不留痕: -VersionDryRun

# 手工构建(仅当前平台)
go build -trimpath -ldflags "-s -w" -o yugsight_windows_amd64.exe .

# 探针端 = 独立程序(装到被扫描机器上; 只做出站连接, 无 Web UI)
go build -trimpath -ldflags "-s -w" -o yugsight-agent.exe ./cmd/agent
# 一条命令产出 6 平台探针包到 agents/(对应中心端 UI"探针下载"页的分发源)
powershell -ExecutionPolicy Bypass -File scripts/build-agents.ps1

# Linux / 其它平台(代码含跨平台桩, 抓包模块仅 Windows 可用)
GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o yugsight_linux_amd64 .
GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o yugsight-agent ./cmd/agent
```

**改动前端后必须先构建前端再编后端**（构建产物被 `go:embed` 嵌入 exe）：

```bash
cd frontend && npm install && npm run build   # 产出 frontend/dist/
cd .. && powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -OutDir dist
```

- `frontend/dist/` **随仓库提交**（它是 `go:embed all:frontend/dist` 的嵌入源，缺失会导致 `go build` 直接失败）。
- 版本号由 `VERSION` 文件管理，构建脚本每次自动末位 +1 并经 `-ldflags -X main.appVersion=` 注入（勿手改 `main.go` 里的兜底值）。
- `npcap-1.86.exe` 不入库（第三方安装器）：需要"抓包驱动一键安装"能力时，自行下载后按此文件名放到仓库根，构建脚本会把它拷进产物。
- 产物只保留平台名版本：不要额外留一个短名 `yugsight.exe`。两者进程名不同，会导致旧实例占住 8420 端口继续用**旧二进制的路由表**应答，新增接口表现为"一直 404"，极难排查。
- UI 改动需重新编译生效；报告/模板/漏洞库/配置放 exe 同目录，无需重编。

## 测试

```bash
go test ./...                    # 全部 Go 单测
go test . -run TestVueFSEmbeddedMatchesDisk   # 校验前端产物确实被嵌入(见下)
```

`TestVueFSEmbeddedMatchesDisk` 守着一条线上踩过的坑：`go:embed` 默认排除以 `_` / `.` 开头的文件，而 Vite 会产出 `assets/_plugin-vue_export-helper-<hash>.js`，漏掉它会导致部分页面点菜单无反应。因此嵌入必须写 `//go:embed all:frontend/dist`，且该用例会逐文件比对磁盘与嵌入内容，少一个就失败。

## 配置文件（settings.json）

全部配置统一在 exe 同目录 `settings.json`（可复制仓库的 `settings.example.json` 改名起步；每节都可选，全缺省=全部默认值，程序照常运行）：

| 节 | 用途 | 默认 |
|---|---|---|
| `engine` | 外部引擎调用 + 一键下载/自动补装 | 关 |
| `ai` | AI 全链路分析（基础参数 / 模块开关 / Prompt 模板 / RAG 文档库 / 结构化记忆库） | 关（模块开关默认开，受全局约束） |
| `capture` | 抓包（环路检测 / 全量采集） | 全量开、环路检测关 |
| `collect` | 节点监控采集（开关 / 间隔 / 并发 / 限速 / 白名单 / NetFlow 接收 / 告警阈值 / 采集任务） | 关 |
| `updater` | Nuclei 模板与 CPE 库在线更新 | 官方仓库通道开、后台自动更新关 |
| `probe` | 分布式探针（center 中心端 / client 探针端） | 全关 |
| `scheduler` | 任务队列调度（排队/并发/限速/策略） | 开（即时扫描不受影响） |
| `report` | 报告生成引擎（评分/拓扑/历史对比/自动触发）+ 原始报告（`autoSave` 执行完成自动存档 / `maxRaw` 存储上限） | 开（`autoSave` 默认开，`maxRaw` 默认 500） |
| `screen` | 大屏 Prometheus 指标端点 | 关 |
| `database` | 数据库（内置文件引擎） | sqlite 内置 |
| `auth` | 登录开关与初始账密（程序读写） | 开，admin/admin123 |
| `whitelist` | 白名单（程序读写） | - |
| `tls` | HTTPS（`{enabled,cert,key}`，证书缺失降级 HTTP） | 关 |
| `authcheck` | 弱口令检测（目标 CIDR 白名单 + 限速） | 缺失即关 |

- 改完**重启生效**（前端页面上改的配置由程序自动写回本文件，无需重启）。
- 程序自动保存（账号/白名单等）只替换自己的节，你在其它节手写的注释与格式不会丢；兼容 UTF-8 BOM。
- `settings.json` 里没有的节会回退读旧单文件（`engine.json` / `probe.json` 等），从旧版本升级不丢配置；把内容挪进对应节后即可删旧文件。

## 账户与安全

- **初始账号**：全新安装按 `settings.json` 的 `auth` 节 `user/pass` 自动创建（未配置默认 `admin / admin123` 并回写配置文件）；校验始终走 SHA-256 + 随机 salt 哈希，无明文旁门。重置密码 = 删掉 auth 节的 `users`/`salt` 两行后重启
- **2FA 动态码**：常驻启用。登录页直接展示当前 6 位动态码（90 秒时间片），账号 + 密码 + 动态码一屏提交（一次登录，无第二步）；码值本地计算无外网请求，未配置时首次拉取自动初始化
- **记住密码**：1 天内自动回填表单（浏览器 localStorage，动态码仍需输入，不削弱 2FA）
- **登录限流**：5 分钟内失败 5 次锁定 15 分钟
- **多用户 / RBAC**：授权页可创建账号并分配角色 —— `admin` 管理员（全权限）/ `operator` 操作员（除授权管理页外全部功能）/ `auditor` 只读；支持改密/改角色/停用/删除（权限边界见"角色与权限"）
- **测试模式**：exe 同目录存在 `test_mode.txt` 时跳过所有鉴权（开发调试用，正式使用请删除）

## 漏洞库（可导入）

- 内置 10 条常见规则（`scanner/vuln_builtin.json`，编译进 exe）
- **自定义导入**：两种方式 —— UI「引擎与规则 → 规则」页粘贴 JSON 导入（校验后写入 `vuln/` 并立即生效，无需重启）；或直接在 exe 同目录建 `vuln/` 文件夹放入 `*.json`（重启后加载）。UI 中还可查看全部已加载规则与内置规则原始 JSON
- 规则格式（三种 type）：

```json
{
  "rules": [
    { "id": "MY-0001", "name": "目录列表", "severity": "low",
      "type": "body", "pattern": "<title>\\s*Index of /", "detail": "响应为目录列表" },
    { "id": "MY-0002", "name": "ASP.NET 版本", "severity": "info",
      "type": "header", "pattern": "(?m)^X-AspNet-Version: .*\\d", "detail": "版本暴露" },
    { "id": "MY-0003", "name": "敏感路径", "severity": "medium",
      "type": "path", "pattern": "/.env.local", "detail": "路径存在即报" }
  ]
}
```

`body`/`header` 的 `pattern` 是 Go 正则；`path` 的 `pattern` 是探测路径（非 404 即命中）。
规则无需自己从零收集：可参考 Nuclei 社区模板（github.com/projectdiscovery/nuclei）把现成规则转成上述格式导入。

- 生成自用规则包：`nuclei-templates/`（自行 clone 官方仓库到仓库根）→ `go run scripts/nuclei2json.go -dir ./nuclei-templates -out dist/vuln/nuclei.json`

## 外部引擎（可选）

内置引擎开箱即用；需要专业引擎的完整能力（OS 探测 / 容器镜像 / 主动攻击）时：

1. UI「引擎与规则」页的**引擎**页签**一键下载安装**（支持代理 / GitHub 镜像，自动测速选最快），或手动把二进制放到 exe 同目录 `bin/`（`nmapcore` / `trivycore` / `zapcore` / `nucleicore`，前缀匹配即可）
2. `settings.json` 设 `engine.enabled=true` 接入扫描编排：**外部引擎优先，缺失/失败自动降级内置引擎**（超时/取消不算失败，直接透传）
3. ZAP 是 Java 程序：下载模块会**自动装一个专用 JDK 17**（放在 `bin/zapcore/ZAP_<ver>/jre/`，与系统 Java 隔离，不污染 PATH）

默认全关：不启用时不启动任何外部进程，行为与单机内置引擎完全一致。

## 弱口令 / 空口令检测（可选）

- `settings.json` 的 `authcheck` 节启用（**节缺失即关闭，零连接**）；目标 CIDR 白名单外的请求直接拒绝
- 支持 10 种协议：redis / mysql / postgresql / ftp / telnet / ssh / smb / vnc / rdp / oracle，用 top100 常见口令字典（内置）+ exe 同目录自定义字典做**真实试探**
- 明确的能力边界：写不到"可靠判定"的分支一律返回"协议不支持"并在结果里标明（不伪造成"口令错误"）；MSSQL 的 TDS 登录未实现，界面上不展示该协议
- 令牌桶限速 + 尝试次数上限；每次尝试落审计日志（口令只在命中时出现）

## AI 全链路分析（阶段 3，可选插件）

**默认关闭**，关闭时零 LLM 调用。开启方式：`-ai` 参数，或 `settings.json` 的 `ai` 节 `enabled=true`，或在「系统配置 → AI 配置」页点「测试并保存」（连通通过才落盘，热生效免重启）。

**数据流**（完整链路）：

1. 业务页（实时抓包 / 扫描作业 / 弱口令检测 / 节点监控告警）点 **AI 分析** 按钮（AI 未启用或对应模块开关关闭时按钮置灰）；
2. 系统读取 `ai` 节全局参数 + 该模块绑定的 **Prompt 模板**，按需从 **RAG 文档库** 检索 TopK 文档片段、从 **结构化记忆库** 按时间窗/范围检索平台历史（漏洞/告警/抓包报告/节点指标）；
3. 组装变量（`{{raw_data}}` 脱敏截断 / `{{asset_info}}` / `{{scan_result}}` / `{{metric_data}}` / `{{time}}` / `{{structured_memory}}`）+ 系统级固定边界（只解读、不判定、不生成 POC），提交 LLM；
4. 研判结果**回写报告中心对应报告**（`aiNote` 全文 / `aiData` 结构化审计元数据 / `aiAnalyzedAt` 时间）；
5. 报告中心：原始结构化数据 + AI 研判**同时查看**；多选合并时，已分析源的 AI 内容随源报告保留（可逐源展开）。

**RAG 文档库 vs 结构化记忆库**（严格区分）：

| | RAG 文档库 | 结构化记忆库 |
|---|---|---|
| 数据 | 用户上传的**非结构化文档**（基线/手册/资料） | 平台数据库内的**结构化历史**（业务落库） |
| 检索 | 分片 + TF-IDF 向量相似度（内置引擎，离线） | 保留时长 + 范围勾选 + 条数上限，只读 |
| 存储 | `data/ai_docs.jsonl`（独立第 19 表） | 不额外存储（数据源即业务表） |
| 注入 | 模板 RAG 开关开启时进 Prompt 参考段 | 自动注入 `{{structured_memory}}` 变量 |

**安全口径**：后端 Ollama / OpenAI 兼容（同一 `/chat/completions` 协议）；发送前**强制脱敏**（配置层关闭也强制）；只解读不判定，命中永远以扫描引擎为准；LLM 失败不写报告（半截结果落库比没有更糟）。

`ai` 节字段（完整结构见 `settings.example.json`）：

```
基础:   enabled / backend(ollama|openai) / apiBase / apiKey / model /
        timeoutSec / maxContext / maxTokens / temperature / topP /
        retry / maxEvidence / desensitize / maxConcurrency
模块:   modules{capture, scan, monitor}
模板:   prompts{capture, scan, monitor}{name, content, rag, topK}
文档库: rag{enabled, topK, chunkSize, maxChunks, maxDocs}
记忆库: memory{enabled, retainDays, maxItems, compress,
        scopes{assets, alerts, captures, metrics}}
```

**API**（除 `/api/ai`、`/api/ai/test` 外需登录，写操作需 admin/operator）：`GET /api/ai`（状态+配置总览）、`POST /api/ai/config`、`POST /api/ai/test`、`GET/POST /api/ai/templates[+/reset]`、`GET /api/ai/rag`、`POST /api/ai/rag/config`、`POST /api/ai/rag/docs`、`POST /api/ai/rag/docs/{id}/toggle`、`DELETE /api/ai/rag/docs/{id}`、`GET /api/ai/rag/search?q=`、`GET/POST /api/ai/memory`、`POST /api/ai/analyze`（`{reportId}` 或 `{module}`，回写报告中心）。

## 报告模板

- **报告生成引擎**（`settings.json` 的 `report` 节启用，默认关闭）：风险评分、修复建议、资产拓扑、两轮扫描历史对比（新增/修复/持续存在三分桶）、扫描结束自动触发；PDF 走浏览器打印通道（纯标准库无 PDF 库），由浏览器另存为
- 默认模板已内置（`web/report.html`），导出为 A4 排版 HTML：封面（标题/风险等级/目标/操作者）、风险概况统计、逐次扫描明细（发现 + 结果表）、总体建议、免责声明
- **自定义模板**：在 exe 同目录放 `report_template.html`（Go text/template 语法），修改后立即生效（无需重启）
- 可用变量：`.Title` `.Operator` `.Tool` `.Time` `.RiskLevel`(高/中/低/无) `.TotalFindings` `.High` `.Medium` `.Low` `.Info`，`.Scans` 数组（每项含 `typeName` `target` `startTime` `duration` `summary` `rowHead` `rows` `findings[severity/title/detail]`），函数 `add`

## 报告中心（二期：原始报告底座）

「报告中心 → 原始报告」页签：四大业务模块执行完成后的**原始结构化结果**自动存到这里 —— 只存原始数据、不做加工，供后续 AI 模块直接读取分析（本阶段**不开发 AI**，AI 结果字段已预留）。

**存储时机（各模块的"执行完成"定义）**：

| 来源模块 | 触发点 | 来源标记 |
|---|---|---|
| 实时抓包 `capture` | 点"停止抓包"（含抓包子进程异常退出，缓冲里已有的报文同样留档） | `local` |
| 扫描作业 `scan` | 本地扫描管线收尾（含外部引擎编排路径）+ 探针回传落库完成 | `local` / `engine` / `probe:<节点ID>` |
| 弱口令检测 `weakpass` | 批量探测批次结束（含手动中止，部分结果留档） | `local` |
| 节点监控 `monitor` | 连续采样过程：**周期轮询不自动存档**（60s 一轮会刷屏），只在"立即采集一轮"完成时自动存档，另可在节点监控页手动"存快照到报告中心" | `monitor` / `collect` |

自动存档是 best-effort：失败只记日志，绝不影响业务主流程；`settings.json` 的 `report.autoSave=false` 可整体关闭（默认开，与报告引擎同为只读聚合、不改执行链路）。

**列表字段**：报告（标题+一行摘要）/ 来源模块（彩色徽标：实时抓包、扫描作业、弱口令、节点监控、合并报告）/ 来源标记（执行节点 + 操作人）/ 资产（前 3 个 IP，超出显示总数）/ 关键统计（各模块口径：报文数、漏洞/资产/存活、目标/命中、目标/在线）/ 标签 / 生成时间 / 操作（查看、删除）。

**筛选**：来源模块（带计数）/ 标签 / 资产 IP（支持前缀子串）/ 时间范围（起~止日期）/ 关键字（标题、摘要、来源标记），可组合。

**合并逻辑**（多选 → 一份汇总报告）：

- 勾选 **≥2 份**原始报告，填可选的合并标题与标签，点"合并为汇总报告"；
- 合并是**整合不是聚合**：各源报告正文按来源模块分组进 `sections`（固定顺序：抓包→扫描→弱口令→监控→合并），**原文照搬不改写** —— 后续 AI 读到的仍是原始结构；
- 资产、标签取**并集**；`sourceIds` 记录全部源报告 ID（合并报告详情里可下钻到每一份源报告）；统计做加法（条目总数 + 各模块报告数）；
- 合并报告本身也是一份普通原始报告：可再被合并、可筛选、可删除；**源报告不被合并消耗**（独立保留）；
- 合并结果有 8MB 正文上限（防多份大报告把存储撑爆），超限时提示减少合并数量。

**数据存储结构**（`data/raw_reports.jsonl`，每份报告一行，与其余表同引擎）：

```json
{
  "id": "rr_20260923_1a2b3c",
  "module": "scan",
  "title": "Web扫描报告 http://10.0.0.5",
  "source": "engine",
  "operator": "admin",
  "createdAt": "2026-09-23T10:00:00+08:00",
  "tags": ["扫描", "Web"],
  "target": "http://10.0.0.5",
  "assets": ["10.0.0.5"],
  "durationMs": 1234,
  "summary": "3 个漏洞 / 1 个资产 / 1 台存活",
  "stats": { "items": 3, "extra": { "assets": 1, "alive": 1 } },
  "payload": { "……各模块自己的原始结构化结果(自包含)……": "" },
  "sourceIds": null,
  "aiAnalyzedAt": null,
  "aiNote": "",
  "aiData": null
}
```

- `payload` 是原始结果的完整 JSON：抓包 = 会话参数+统计+事件+环形缓冲内全部报文（≤2000 条）；扫描 = 漏洞+资产+存活+端口（与落库同口径，已过白名单/误报过滤）；弱口令 = 批次结果+审计；节点监控 = 目标配置+最新样本/轮次+最近异常事件（口令字段在展示层剥离，与 API 回显同口径）；
- 合并报告（`module=merged`）的 `payload` 固定为 `{mergedFrom: [源报告引用], sections: [{module, count, reports: [源正文…]}]}`；
- **AI 预留字段**：`aiAnalyzedAt` / `aiNote` / `aiData` 本阶段恒为空，三期 AI 模块分析后直接写回这三个字段（报告本体不动，结构已随报告持久化，届时无需迁移）；
- 存储上限 `report.maxRaw`（默认 500 份），超限按时间淘汰最旧；单份 `payload` 上限 8MB；
- 权限与其它报告操作一致：浏览全角色可，写操作（删除/合并/快照）限管理员/操作员。

**API**（`/api/v2/raw/`，均 requireAuth + 写操作 adminOrOperator）：`GET /list`（轻量，不带 payload）、`GET /{id}`（详情含 payload）、`DELETE /{id}`、`POST /merge`（ids+标题+标签）、`POST /snapshot`（monitor/collect 手动存快照）、`GET /options`（模块计数/标签/资产/时间范围）。

## 分布式扫描（中心端 + 探针端）

两个独立程序，各有各的部署位置：

| 程序 | 部署位置 | 作用 |
| --- | --- | --- |
| `yugsight_windows_amd64.exe` | 中心机器 | Web UI、本地扫描、探针管理、任务下发、结果落库 |
| `yugsight-agent.exe` | 各探针机器 | 上报节点信息、接收并执行任务、回传结果（无 Web UI、零入站端口） |

**中心端**：exe 同目录 `settings.json` 的 `probe.center` 节（或启动加 `-probe=center`）：

```json
{ "probe": { "center": { "enabled": true, "listen": ":8600", "token": "你的密钥" } } }
```

**探针端**：把 `yugsight-agent.exe` 拷过去，同目录放 `settings.json` 的 `probe.client` 节：

```json
{ "probe": { "client": { "enabled": true, "centerAddr": "192.168.1.10:8600", "token": "你的密钥" } } }
```

也可以直接用命令行（免配置，适合容器/批量部署）：

```
yugsight-agent.exe -center 192.168.1.10:8600 -token 你的密钥
```

探针包无需手工拷：中心端 UI「节点监控 → 探针节点管理」提供**下载探针**入口（`agents/` 目录下的 6 平台包，由 `scripts/build-agents.ps1` 产出），页面还给出逐平台的部署命令；探针支持**自动更新**（中心端版本比对，带签名的临时 URL 下发）。

探针日志写 exe 同目录 `yugsight-agent.log`。断线自动重连（指数退避，上限 60s），中心端恢复后自动重新上线。

**默认全关**：不写 `probe` 节时，两个程序都保持单机 / 待命状态，不监听端口、不发起外连。

> 提示：为确保两台机器通信正常，中心端 `listen` 需绑定到探针可达的地址（如 `0.0.0.0:8600`），并放行该端口。

## 节点监控（阶段 1：采集底座）

「诊断与观测 → 节点监控」（/nodemonitor）是主机侧与网络侧的统一监控入口，页内两个 Tab。阶段 1 只建**采集底座**（任务调度 / 限速 / 白名单 / 时序存储 / 异常事件 / 标准化输出），报告增强与 AI 不在本阶段。

**默认关闭**（项目规则 5）：`settings.json` 没有 `collect` 节 = 未启用 —— 引擎不跑循环、不监听端口、不发起任何外连；在页面底部「采集配置」区显式开启。

### Tab 1：探针节点管理

上半 = 原「探针管理」全部功能（yugsight-agent 分布式探针）：节点表（状态 / 探针 ID / 名称 / 系统 / 版本 / 地址 / 能力 / 最近心跳）、详情、扫描任务下发、**下载探针**（6 平台安装包 + 逐平台部署命令一键复制）、任务明细。部署与协议细节见「分布式扫描」节。

下半 = **主机侧扩展采集（无代理）**：目标机上装不了探针时走协议采集，三个协议：

| 协议 | 目标填法 | 采集内容 |
|---|---|---|
| WinRM | `host:5985`（HTTP）/ `host:5986`（TLS） | CPU、内存、各盘容量、进程 TOP10（按内存） |
| SSH 命令采集 | `host:22` + 用户名，**仅密钥登录**（BatchMode 拒绝交互口令） | CPU（/proc/stat 双采样差分）、内存、负载、运行时长、磁盘、进程 TOP10、最近系统告警 |
| 主机 SNMP | `host:161` + 社区串（v2c）或 v3 认证 / 加密 | HR-MIB 只读：CPU / 内存 / 磁盘 / 运行时长 |

### Tab 2：网络设备监控

上半 = 既有 SNMP 设备监控（v2c / v3 目标，轮询间隔 ≥5 秒，CPU / 内存 / 流量 / 接口 up 数，随时「立即采集一轮」；全程只读 GET/GETBULK，不改动设备配置）。

下半 = **网络侧扩展采集（SNMP 之外）**，四个协议：

| 协议 | 目标填法 | 采集内容 |
|---|---|---|
| ICMP 链路探测 | `ip`（探测次数 1–20） | 平均 / 最小 / 最大时延、抖动、丢包率 |
| NetFlow/IPFIX | **监听地址**（默认 `0.0.0.0:2000`，UDP 接收，设备把导出指向它） | 活跃流数、流入速率（bps/pps）、TOP5 五元组流；v5 累计计数器自动做差分 |
| NETCONF | `host:8300` + 用户名 / 口令，TLS 通道（RFC 8012 行分隔 XML RPC） | 接口状态 + 数值计数器（按 openconfig → ietf-interfaces → 全量兜底顺序尝试） |
| RESTCONF | `host:443` + 用户名 / 口令，HTTPS + JSON（YANG） | 接口状态 + 计数器（数据路径默认 `if:interfaces`，可改） |

### 采集配置与异常事件

- **采集配置**（页面底部，两 Tab 共用，写入 `settings.json` 的 `collect` 节，保存即热生效、无需重启）：总开关 / 默认间隔（≥5 秒，每任务可单独覆盖，0=用全局）/ 并发任务数 / 全局限速（每秒最多 N 个采集动作，令牌桶）/ 时序保留时长 / **IP 白名单**（IP 或 CIDR，留空=不限制；非空时只放行白名单内目标，防误配成对外网段发流量；NetFlow 是被动接收不拦）/ NetFlow 接收开关 + 监听地址 / **告警阈值**（CPU % / 内存 % / 时延 ms / 丢包 % / 连续失败 N 轮判离线）。
- **口令**（SNMP 社区串与 v3 口令、WinRM / SSH / NETCONF / RESTCONF 的账密）密文存储：密钥取环境变量 `YUGSIGHT_MONITOR_KEY`，未设置时页面提示将以明文存于 settings.json；API 永不回传明文（只回 `has*` 布尔），编辑时留空 = 不修改。
- **异常事件**全部**边缘触发**（不每轮重复报）：连续失败 N 轮 → `offline`（critical）；失败后恢复 → `recover`（info）；指标从低于阈值跨到达到/超过 → `high_cpu` / `high_mem` / `high_rtt` / `high_loss`（warn）。事件落 `collect_events` 表（保留 30 天），页面事件区可查，同时经 SSE 实时广播。
- **历史时序**：每轮结果落 `collect_samples` 表（保留时长 + 每任务轮数双限，60 秒间隔约 24 小时）；任务行「历史」按钮看最近 30 轮（时间 / 成功失败 / 全部指标）。

### 公共基础能力与能力边界

- **标准化输出**：所有协议产出统一为 `Metric`（名字 + 数值 + 单位 + 标签）—— 进程列表、流统计、系统事件也是同一结构，时序存储 / 前端 / 报告接入只有一条路；`ReportSink` 接口是报告中心的预留入口（阶段 1 空实现，**不实现 AI**）。
- **采集调度独立于扫描调度**：scheduler 是"一次性任务排队"（为扫描设计，槽位与限速都是扫描语义），采集是"周期轮询" —— collect 包独立 1 秒 tick 循环，不占扫描并发槽位，两者互不干扰。
- **主机 SNMP ≠ 网络 SNMP**：同一协议、两套独立数据源 —— Tab 2 上半是既有 monitor 包（网络设备 MIB，独立表 monitor_samples），Tab 1 下半的主机 SNMP 是 collect 包的 HR-MIB 采集器（落 collect_samples），页面同屏展示但互不混。
- 能力边界（不支持的如实报错，不做假降级）：NETCONF 仅 TLS 通道（RFC 8012），只支持 SSH 通道（6242）的设备不支持；SSH 仅密钥登录（自动化场景弹口令会挂死进程）；NetFlow 支持 v5 与 IPFIX，v9 收包即忽略；WinRM 用 HTTP Basic 认证（Negotiate / 域环境不支持）；RESTCONF 数据路径由设备 YANG 模型决定（默认接口模型）。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 点菜单没反应、控制台报 `Failed to fetch dynamically imported module` | 页面引用的前端资源没取到。① 升级/重新构建后**旧标签页**里的 chunk hash 已失效 → Ctrl+F5 强刷；② 构建时漏了前端产物（`frontend/dist/` 未提交或未 `npm run build`）→ 见"构建与重新编译" |
| 服务进程还在、端口也在听，但怎么都连不上 | 绑定的是**单个 IP**且该 IP 已不在本机（DHCP 换租 / 插拔 VPN / 网卡切换）。默认已绑 `0.0.0.0`（全部网卡）不受影响；若用 `-bind-local` 启动，重新启动进程即可恢复正常 |
| 启动后端口不是 8420 | 8420 起连续 20 个端口被占用时会自动顺延，真实地址看控制台标题栏或启动日志的 `UI 地址` |
| 想清空历史数据（漏洞记录 / 审计日志） | 漏洞记录：**漏洞管理**页右上「清空全部漏洞」（admin/operator，需输入"清空"确认，只清漏洞表、资产台账不动）；审计日志：**授权管理**页审计区的「清空日志」或行内「删除」（仅 admin）。两者都会留下清理审计记录，属设计如此 |
| 找不到"停止服务"按钮 | 只在两处：登录页底部链接、授权管理页"服务管理"卡片（`/api/quit` 免登录）。关控制台窗口不会停服务 |
| 抓包页提示"未找到安装器" | exe 同目录缺 `npcap-1.86.exe`（构建时未附带），从 Nmap 官网下载该版本放到 exe 同目录即可 |
| 大屏地球白屏 / 地理信息全 unknown | exe 同目录缺 `globe/` 或 `geoip/` 数据（构建时 `build/` 下对应目录缺失会跳过），属降级而非报错：跑 `scripts/geoip_sync.go` 生成后重新构建 |
